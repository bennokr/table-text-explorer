# v0.1

The main page is the application. The initial feasibility harness remains separately
available at `/feasibility.html`.

## Workspace

- Top left: a fixed, responsive Bokeh Canvas scatter. Choose data axes, color by a
  categorical field, or explicitly fit UMAP/PCA/SVD on all rows. Brush/lasso/tap to
  highlight. The highlighted set does not itself filter or trigger a refit.
- Bottom left: a native table with vertical row virtualization, horizontal scrolling,
  sticky headers, sorting and click/Ctrl/Meta/Shift record selection.
- Top right: an independently scrollable chart stack. Add/remove histograms, category
  frequencies, text-length distributions, numeric/date scatters, categorical/numeric
  strip plots, or categorical heatmaps. Aggregate selection maps back to row IDs;
  highlighting updates selected-count overlays. Categories beyond the first 29 are
  grouped as Other. No association tests/statistics are computed.
- Bottom right: every field of the active record, with full multiline values and
  independent vertical scrolling. Navigation follows visible/sorted records. Add an
annotation column and assign or clear a label for highlighted records.

The toolbar contains local file import, a dynamically generated fixture picker,
table export, a search expression, explicit filter-to-highlighted and reset controls,
and a native Settings dialog. Glyph controls have native tooltips and accessible names.
Spacing is compact; the base UI text is 12px.

## Types and search

Original values are preserved independently of chart/analysis conversion. Empty
strings/null/undefined count as missing. Auto categoricals use repeated integer codes
with at most eight levels; text uses at most eight distinct values or at most 10%
distinct values, within the configurable cardinality ceiling (default 50). SAV value
labels add categorical evidence. ID names and unique sequential columns avoid automatic
categorical conversion. Other numeric columns stay numeric; ISO and dotted
DD.MM.YYYY dates have calendar validation. Settings allows explicit type overrides.

Search supports free text, quoted terms/column names, `field:value` contains matching,
`field=value`, `!=`, numeric/date comparisons, token prefixes (`word*`), `field:null`,
implicit AND, explicit AND/OR/NOT, and parentheses. It maintains a schema-aware AST with
AND-before-OR precedence. Exact column names take priority; otherwise an unambiguous
case-insensitive name is accepted. Invalid or unfinished input leaves the last valid
filter active. Pill editing/autocomplete and full linguistic FTS are future work.

Filters are intersected with an explicit snapshot of highlighted row IDs. Changing
the highlighted set later does not change that filter snapshot. Reset clears both
the query and explicit filter, while retaining existing projection coordinates.

## Workers and privacy

Pyodide/scikit-learn runs in a persistent module worker. Table features use median
numeric imputation, categorical one-hot features and variance scaling. Text features
use selected columns, TF-IDF words/bigrams and configurable basic NL/EN stopwords.
SVD bounds dense intermediate features at 32 dimensions before PCA/UMAP; PCA therefore
operates on that reduced space for wide tables. UMAP runs in a separate seeded worker
with progress updates. Cancellation terminates workers; later fits initialize them again.

New annotation columns are excluded from automatically chosen projection features;
they can still be explicitly selected in Settings.

Importing a different table cancels old work. Search/highlighting/filtering never
refits. Settings applies to the next explicit fit. The model-free path requires no
WebGPU or WebGL. Static runtime files can be downloaded during asset preparation or
bundled locally; user records/text/coordinates are never sent to another service.

CSV, JSON records, SAV and XLSX import are supported. XLSX currently uses the first
worksheet. Export is CSV/JSON/XLSX with all or filtered original rows plus annotation
columns; no analysis arrays or SAV export. JSON preserves nested values; table formats
serialize nested values to text where required. Annotation changes are in memory until
export, so export before closing the page. Topic/cluster naming dictionaries, model
selection, chunking and clustering/topic controls remain later-stage work.

## Validation

`npm test` covers schema inference, date validity, query precedence/case/nesting,
annotation preservation, filter snapshots, group-to-record mappings and unusual keys.
`npm run check` enforces Ruff/ESLint/readability budgets. `npm run test:browser` tests
the production bundle with GPU APIs disabled and all external traffic blocked.
It loads the supplied CSV/SAV/XLSX fixtures, exercises real selection, dynamic charts,
search, annotation downloads in all three export formats, type overrides without
refitting, cancellation and both workers. It imports a synthetic 1,200-row JSON table
to check virtualization, switches back to a smaller fixture after scrolling, and
checks the chart stack at a 1024px viewport. Aggregate results are written to
v0.1-results.json (historical report removed).
